# Featured products

## But

Changer regulierement les produits affiches en feature pour eviter la
redondance sur le site et montrer des articles avec de belles images.

## Règle de sélection

La qualité des images prime sur la date de publication. Ne pas privilégier
systématiquement les nouveautés et ne pas imposer de quota de nouveaux articles.
Choisir les meilleures photos après revue visuelle, puis équilibrer la sélection
pour varier les cadrages, fonds, couleurs, catégories et vendeurs. Éviter les
séries de photos similaires et les répétitions avec le batch immédiatement précédent.
Les articles d’anciens batchs peuvent être repris si leurs images restent parmi
les meilleures. La fraîcheur de publication sert seulement de critère secondaire.

## Fichiers utiles

- `scripts/build-featured-contact-sheets.mjs` : genere des planches visuelles
  pour choisir les meilleurs produits.
- `scripts/apply-featured-products.mjs` : applique le batch en base via
  Supabase.
- `docs/business/featured-products-shortlist.md` : shortlist de travail.
- `docs/business/featured-products-batch-2026-10-30.md` : trace du batch
  courant.

## Workflow

Generer les planches de selection :

```bash
npm run featured:contact-sheets
```

Mettre a jour la shortlist ou le batch cible si necessaire, puis appliquer en
base :

```bash
npm run featured:apply
```

Rafraichir ensuite les produits locaux :

```bash
npm run fetch:products
```

Verifier les changements :

```bash
git status
npm run build
```

Le lint global peut signaler des problemes preexistants de l'application. Quand
on touche seulement aux scripts ou a la doc, privilegier aussi une verification
ciblee des fichiers modifies.
