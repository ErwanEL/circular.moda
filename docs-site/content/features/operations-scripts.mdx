# Operations metier et scripts

## Version simple

Le projet contient plusieurs scripts pour aider a exploiter le site sans tout
faire a la main dans Supabase : tester la connexion, recuperer un cache local de
produits, choisir les produits mis en avant, corriger les images et importer des
contacts utilisateurs dans Brevo.

Ces scripts ne sont pas des pages publiques, mais ils font partie du projet. Ils
doivent etre documentes parce qu'ils peuvent modifier la base ou preparer des
donnees utilisees en production.

Cette page documente les scripts disponibles aujourd'hui. Les pistes non encore
implementees autour de l'optimisation image sont separees dans
[`Pipeline images et media produit`](/features/pipeline-images), section
`Pas encore fait`.

<details>
<summary><strong>Maintenance Supabase Storage images</strong></summary>

Le 27 aout 2026, le projet a depasse le quota Supabase Free Plan a cause de
fichiers sous `storage/products/` qui n'etaient plus references par
`products.images`.

Le diagnostic a donne :

- `2333` objets storage avant nettoyage final ;
- `1967` chemins encore references par des produits ;
- `366` images orphelines supprimees ;
- environ `290.8 MB` recuperes ;
- `791.6 MB` restants sous `storage/products/` apres suppression ;
- `0` candidat orphelin restant au post-audit.

Commandes :

```bash
npm run storage:images:audit
node scripts/delete-supabase-orphan-images-safe.mjs
node scripts/delete-supabase-orphan-images-safe.mjs --delete-confirmed
```

`storage:images:audit` est non destructif. Il compare les objets du bucket avec
les URLs encore presentes dans `products.images`.

`delete-supabase-orphan-images-safe.mjs` est l'outil a privilegier avant une
purge : il genere un plan dans `reports/`, protege les images referencees par
les produits et scanne aussi les references locales du repo. Sans
`--delete-confirmed`, il ne supprime rien.

Ne pas lancer `--delete-confirmed` sans avoir relu le resume du dry-run. Les
suppressions Supabase Storage sont distantes et irreversibles.

</details>

<details>
<summary><strong>Featured products</strong></summary>

Le workflow featured products est operationnel :

1. recuperer ou verifier le cache produits ;
2. generer des contact sheets pour revue visuelle ;
3. choisir une liste de SKUs ;
4. lancer `featured:apply` sans `--apply` pour preview ;
5. relancer avec `--apply` pour ecrire dans Supabase.

Le script d'application vide d'abord les featured existants, puis marque les
SKUs fournis comme `featured = true`.

Les notes business historiques sont dans `docs/business/`.

</details>

<details>
<summary><strong>Imports Brevo et donnees sensibles</strong></summary>

`import-supabase-users-to-brevo.mjs` lit Supabase Auth avec pagination, joint les
profils `users`, normalise le telephone et upsert les contacts dans Brevo.

Toujours lancer d'abord :

```bash
node scripts/import-supabase-users-to-brevo.mjs --list-id=4 --dry-run
```

La sortie peut contenir des emails. Ne pas copier cette sortie dans la doc, dans
un ticket public ou dans un prompt partage.

</details>
