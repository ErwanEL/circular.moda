# Couche data Supabase et APIs publiques

## Version simple

La plupart des donnees du site viennent de Supabase : produits, vendeurs,
categories, couleurs, genres, abonnements newsletter et cycles d'envoi.

Le code contient une couche de helpers pour transformer les lignes Supabase en
objets utilisables par l'UI. Cette couche evite que chaque page connaisse les
details de noms de colonnes, anciens formats ou formats d'images.

Des routes API exposent les produits, les filtres, le profil connecte, les
uploads et les actions newsletter.

## Version detaillee

<details>
<summary><strong>Clients Supabase</strong></summary>

Le repo contient plusieurs clients Supabase :

- client browser pour les pages client ;
- client server SSR pour Auth/cookies ;
- client service role/anon historique pour les helpers serveur et scripts.

Avant un refactoring, verifier quel client est utilise :

- un client publishable peut etre expose cote navigateur ;
- la service role key doit rester uniquement serveur/scripts ;
- les routes API doivent refaire leurs controles d'auth et d'ownership.

</details>

<details>
<summary><strong>Transformation produits</strong></summary>

La table `products` peut exposer plusieurs formats de colonnes selon l'historique
du projet : `name`, `Product Name`, `price`, `Price`, `images`, `Images`, etc.

`supabase-products.ts` transforme ces lignes vers le type `Product` attendu par
l'UI. `product-transformer.ts` transforme ensuite les produits en cartes
catalogue.

Cette compatibilite historique est importante : ne pas supprimer un fallback
sans verifier les donnees Supabase et les anciens imports.

</details>

<details>
<summary><strong>APIs disponibles</strong></summary>

APIs catalogue et options :

- `GET /api/products`
- `GET /api/categories`
- `GET /api/colors`
- `GET /api/genders`
- `GET /api/image`
- `POST /api/revalidate`

APIs vendeur :

- `GET /api/me`
- `PUT /api/me`
- `POST /api/me/upload-product`
- `GET /api/me/products/[id]`
- `PUT /api/me/products/[id]`
- `DELETE /api/me/products/[id]`

APIs admin :

- `GET /api/admin/users`
- `POST /api/admin/users`
- `POST /api/admin/upload-product`
- `POST /api/admin/ai-analyze-product`

APIs newsletter :

- `POST /api/catalogue-subscribe`
- `GET /api/catalogue-test-send`
- `POST /api/catalogue-test-send`
- `GET /api/cron/send-catalogue`
- `POST /api/webhooks/brevo-transactional`

</details>
