# Blog MDX et contenu editorial

## Version simple

Le blog permet de publier des articles depuis des fichiers MDX dans le depot.
Chaque fichier devient un article public avec son slug, sa page detail, son
image, son extrait, son auteur et ses metadata SEO.

La page `/blog` liste les articles publies. Chaque article est disponible sur
`/blog/[slug]`. Les articles peuvent afficher un hero, le contenu principal et
des articles lies.

Le blog est statique : les pages sont generees au build a partir des fichiers
dans `content/blog`.

## Version detaillee

<details>
<summary><strong>Source de contenu</strong></summary>

Les articles vivent dans `content/blog/*.mdx`.

Le nom du fichier devient le slug. Exemple :

```text
content/blog/mon-article.mdx -> /blog/mon-article
```

Le frontmatter controle les informations principales :

- `title`
- `excerpt`
- `author`
- `publishedAt`
- `updatedAt`
- `featuredImage`
- `readTime`
- `published`

Seuls les articles avec `published: true` sont retournes par
`getAllBlogArticles`.

</details>

<details>
<summary><strong>Rendu des pages</strong></summary>

La page `/blog` lit tous les articles publies, trie du plus recent au plus
ancien et affiche l'article principal en carte mise en avant.

La page `/blog/[slug]` :

1. genere les slugs statiques avec `generateStaticParams` ;
2. charge l'article par slug ;
3. genere les metadata avec `generateBlogMetadata` ;
4. rend `BlogHero`, `BlogContent` et `RelatedArticles`.

`revalidate = false` indique que les articles sont pleinement statiques. Pour
mettre un article a jour en production, il faut reconstruire/deployer le site.

</details>

<details>
<summary><strong>Articles lies, tags et recherche</strong></summary>

Le code contient des helpers pour :

- recuperer les articles recents ;
- chercher dans les titres, extraits et contenus ;
- recuperer des articles lies ;
- formater la date ;
- calculer le temps de lecture.

Le composant `BlogTags` existe pour une interface de tags, mais les articles
charges actuellement initialisent `tags` avec un tableau vide dans `blog.ts`.
Si on veut activer un vrai filtrage par tags, il faut lire les tags du
frontmatter et verifier les composants `BlogFilter` / `BlogTags`.

</details>

<details>
<summary><strong>SEO blog</strong></summary>

Le blog genere :

- metadata globales sur `/blog` ;
- metadata dynamiques pour chaque article ;
- Open Graph type `article` ;
- image sociale quand `featuredImage` existe ;
- entree sitemap pour chaque article publie.

</details>

<details>
<summary><strong>Tester la feature</strong></summary>

Tests manuels :

1. Ajouter ou modifier un fichier `.mdx` dans `content/blog`.
2. Verifier que `published: true` est present.
3. Ouvrir `/blog`.
4. Ouvrir `/blog/[slug]`.
5. Verifier le hero, le contenu, les articles lies et les metadata.

Tests techniques :

```bash
npm run build
```

</details>
